# Архитектура

Kolaars Music — обычное Electron-приложение из трёх процессов. Главный процесс отвечает за
файлы, сеть и хранение; интерфейс получает к ним доступ только через узкий мост; общий слой
(`src/shared`) не зависит ни от Node, ни от DOM и используется всеми сторонами.

```
┌──────────────────────────── main (CommonJS) ────────────────────────────┐
│ index.ts   окно, схема kmedia://, CSP, единственный экземпляр           │
│ ipc.ts     все ipcMain.handle — единственная точка входа для интерфейса │
│ db.ts      kolaars.json: атомарная запись + debounce                    │
│ media.ts   привилегированная схема kmedia:// со списком путей           │
│ http.ts    fetch с таймаутом, ретраями и LRU-кэшем                       │
│ localFiles.ts / downloads.ts   импорт файлов, офлайн-загрузки            │
│ providers/ archive.ts, lyrics.ts   внешние API                          │
│ lyrics/pack.ts   встроенный сборник текстов                             │
└─────────────────────────────────┬───────────────────────────────────────┘
                                  │ ipcMain.handle / webContents.send
┌─────────────────────────────────┴───────────────────────────────────────┐
│ preload   window.kolaars — типизированный мост, разворачивает IpcResult  │
└─────────────────────────────────┬───────────────────────────────────────┘
                                  │ contextBridge (sandbox, contextIsolation)
┌─────────────────────────────────┴───────────────────────────────────────┐
│ renderer  React 19 + zustand: state/, views/, components/, styles/       │
└─────────────────────────────────────────────────────────────────────────┘
```

## Общий слой (`src/shared`)

| Файл | Содержимое |
| --- | --- |
| `types.ts` | Доменная модель: `Track`, `Lyrics`, `Playlist`, `Settings`, `SessionState`, `PersistedDb`, `IpcResult`. |
| `ipc.ts` | Константы каналов `CH`, события `EV`, тип `MediaCommand`. Единственное место, где перечислены имена каналов. |
| `defaults.ts` | `DEFAULT_SETTINGS`, `DEFAULT_SESSION`, `createDefaultDb()`, `formatTime()`, `makeId()`, `safeFileName()`. |
| `lrc.ts` | Единственная реализация разбора и сериализации LRC. |

Правило: `src/shared` компилируется и в Node, и в браузер, поэтому здесь нет `node:*`,
`electron` и обращений к `window`.

## IPC

`src/shared/ipc.ts` объявляет каналы, `src/main/ipc.ts` их реализует, `src/preload/index.ts`
выставляет типизированный `window.kolaars`. Каждый обработчик возвращает конверт
`IpcResult<T> = { ok: true, data } | { ok: false, error }`; мост разворачивает его, превращая
ошибку в исключение, поэтому интерфейс пользуется обычным `try/catch`.

Направления:

- **renderer → main**: `ipcRenderer.invoke` — загрузка документа, работа с плейлистами,
  текстами, провайдерами, файлами и загрузками.
- **main → renderer**: `webContents.send` по событиям `EV` — состояние окна, прогресс
  загрузок и импорта, медиа-команды из меню и системных клавиш.

Меню приложения (`src/main/menu.ts`) не выполняет действия само: оно отправляет
`MediaCommand`, а интерфейс решает, что с ним делать. Так одна и та же логика работает и для
меню, и для горячих клавиш, и для медиа-клавиш Windows.

## Хранение (`db.ts`)

Единый документ `kolaars.json` в `app.getPath('userData')`:

- чтение при старте, слияние с текущими значениями по умолчанию (`migrate()`), поэтому старый
  файл после обновления не ломается;
- изменения — через `updateDb(fn)`, запись откладывается на 400 мс (debounce) и сериализуется
  в цепочку промисов, чтобы конкурентные записи не перемешивались;
- сама запись атомарна: сначала `kolaars.json.tmp`, затем `rename`;
- при выходе `flushAndClose()` дописывает документ;
- повреждённый файл не перезаписывается, а переименовывается в `kolaars.json.corrupt-<время>`.

Рядом живут `downloads/` (офлайн-аудио) и `covers/` (вырезанные обложки).

## Медиа-протокол `kmedia://`

Интерфейсу не выдаётся доступ к `file://`. Вместо этого главный процесс регистрирует
привилегированную схему (`media.ts`):

1. файл, который нужно воспроизвести, регистрируется через `allowMediaPath()` или
   `allowMediaRoot()`;
2. интерфейс получает `kmedia://local/<base64url пути>`;
3. обработчик схемы проверяет путь по нормализованному списку разрешённых и отдаёт файл через
   `net.fetch(pathToFileURL(...))` — это прозрачно поддерживает Range-запросы, а значит
   перемотку внутри локального трека.

Схема объявляется до `app.whenReady()` (`registerMediaScheme`) и устанавливается после
(`registerMediaProtocol`).

## Безопасность

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`;
- в окне нет Node — только `window.kolaars`;
- переходы по внешним ссылкам открываются системным браузером, навигация окна ограничена;
- CSP применяется и к собранному приложению: `script-src 'self'`, `object-src 'none'`,
  `frame-ancestors 'none'`, изображения и медиа — с `kmedia:`, `blob:` и `https:`;
- единственный экземпляр приложения (`requestSingleInstanceLock`).

## Состояние интерфейса

Три хранилища `zustand` в `src/renderer/src/state`:

| Файл | Ответственность |
| --- | --- |
| `store.ts` | Маршрут, каталог и его индекс, плейлисты, избранное, настройки, очередь, панели, тосты. Загружает документ при старте (`bootstrap`) и разрешает идентификаторы (`resolveTracks`). |
| `player.ts` | Движок воспроизведения: элемент `<audio>`, очередь, повтор, перемешивание, громкость, восстановление сессии. |
| `lyrics.ts` | Тексты: поиск по встроенному сборнику, онлайн-поиск, сохранение, черновики мастерской. |

Ключевое правило: **списки хранят только идентификаторы**. Плейлисты, избранное, очередь и
сессия ссылаются на треки по `id`, а сами треки лежат в словаре `tracks` документа и в
встроенном каталоге. Всё разрешение сосредоточено в `resolveTracks(ids)`: он отбрасывает
идентификаторы `arc:…`, которых нет в индексе, запрашивает их у Internet Archive и
кэширует результат. Благодаря этому документ не растёт от размера библиотеки, а треки,
найденные онлайн, «оживают» после перезапуска.

## Встроенные данные

- `data/seed-catalog.json` — 211 треков и 10 подборок. Собирается из живых запросов Internet
  Archive (`scripts/build-seed-catalog.mjs`), читается главным процессом из
  `process.resourcesPath` в собранном приложении.
- `data/lyrics-pack.json` — 65 песен общественного достояния. Импортируется прямо в бандл
  главного процесса (`src/main/lyrics/pack.ts`), поэтому не требует файлового доступа.

## Сборка

`electron-vite` собирает три конфигурации независимо (см. `electron.vite.config.ts`):

| Процесс | Формат | Результат | Особенности |
| --- | --- | --- | --- |
| main | CommonJS | `out/main/index.js` | `externalizeDepsPlugin`, псевдоним `@shared` |
| preload | CommonJS | `out/preload/index.js` | без Node-зависимостей, кроме `electron` |
| renderer | ESM | `out/renderer/` | React 19, псевдонимы `@` и `@shared` |

`music-metadata` — ESM-пакет, а главный процесс — CommonJS, поэтому он загружается
динамическим `import()` и вынесен из asar (`asarUnpack`).

Упаковка — `electron-builder`: NSIS-установщик и портативная сборка для Windows x64.
`electronDist` указывает на `node_modules/electron/dist`, а `downloadAlternateFFmpeg`
выключен, поэтому упаковка не требует загрузок с GitHub. Инструменты правки ресурсов и сборки
установщика (rcedit, 7-Zip, NSIS) кэшируются скриптом `scripts/fetch-builder-tools.mjs`,
который запускается автоматически перед каждой командой упаковки и проверяет каждый архив по
SHA-256.
