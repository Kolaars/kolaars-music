# Источники: YouTube Music и SoundCloud

Экран **«Источники»** добавляет к Kolaars Music поиск и воспроизведение из двух сервисов,
которые публикуют официальные API и официальные встраиваемые плееры:

| Сервис | Поиск | Воспроизведение |
| --- | --- | --- |
| YouTube Music | YouTube Data API v3 | официальный YouTube IFrame Player |
| SoundCloud | официальный публичный API | официальный SoundCloud Widget |

Приложение **не** извлекает аудиопоток, не подделывает подписи, не обходит DRM и не сохраняет
защищённые треки на диск. Звук идёт из плеера самого сервиса; реклама, ограничения и правила
сервиса действуют как обычно.

## Настройка YouTube

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект.
2. В разделе **APIs & Services → Library** включите **YouTube Data API v3**.
3. В разделе **APIs & Services → Credentials** создайте **API key**.
4. Вставьте ключ на экране «Источники» в поле «Ключ YouTube Data API v3» и нажмите
   «Сохранить».

Ключ можно ограничить: для настольного приложения удобнее ограничение по API
(**API restrictions → YouTube Data API v3**). Ограничение по HTTP-рефереру здесь не подходит:
запросы к Data API выполняет главный процесс приложения, а не браузерная страница, поэтому
у них нет referrer сайта.

Квота по умолчанию — **10 000 единиц в день** на проект. Один поиск стоит около 101 единицы
(100 за `search.list` + 1 за `videos.list`), то есть примерно 100 поисков в день. Результаты
кэшируются в памяти на пять минут.

## Настройка SoundCloud

1. Зарегистрируйте приложение в [SoundCloud Developers](https://developers.soundcloud.com/).
2. Получите **client_id** приложения.
3. Вставьте его на экране «Источники» в поле «SoundCloud client_id» и нажмите «Сохранить».

SoundCloud рассматривает новые приложения вручную. Если API отвечает `401`/`403`, значит
`client_id` ещё не одобрен или отозван — приложение покажет это сообщение, а не пустой список.
Часть треков авторы запрещают встраивать. YouTube сообщает это в `status.embeddable`;
если же официальный плеер отказывает уже после загрузки (возрастной фильтр, лицензия,
регион), приложение запоминает это и показывает кнопку «Открыть в YouTube Music». Для
SoundCloud то же самое делает ошибка виджета со ссылкой на страницу трека.

## Как это устроено

- **Поиск** выполняется в главном процессе через `fetch` с таймаутом, повторами и кэшем.
  Ключ никогда не передаётся в рендерер.
- **Ключи** шифруются через Electron `safeStorage` (DPAPI в Windows, Keychain в macOS,
  libsecret в Linux) и лежат в `sources.json` в каталоге данных приложения. В открытом виде
  они не записываются; параметры `key` и `client_id` вырезаются из текстов ошибок.
- **Воспроизведение** монтирует видимую карточку с официальным iframe. Очередь, повтор,
  перемотка и громкость управляются через публичный JS API плеера. Карточку нельзя скрыть
  или оставить только звук: это условие обоих сервисов. Область YouTube-плеера держится не
  меньше 200 × 200 px — минимальный размер по правилам YouTube.
- **Origin интерфейса.** Собранное приложение отдаёт интерфейс локальным HTTP-сервером на
  `127.0.0.1` (порты 41723–41727). Официальный YouTube-плеер отклоняет страницы с
  `file://`-origin (ошибка 153), потому что запрос приходит без referrer. Сервер доступен
  только с этого компьютера и отдаёт только файлы приложения.
- **Очередь и избранное** работают как с обычными треками. Внешний трек попадает в
  библиотеку, когда вы добавляете его в избранное или плейлист; тогда ссылка переживает
  перезапуск, а метаданные подтягиваются тем же API.
- **Загрузки** для внешних треков недоступны — у них нет файла, который можно сохранить.
- **Discord Rich Presence** не превращает внешний трек в скачиваемый. Кнопка «Скачать»
  появляется только у открытых записей Internet Archive с прямой публичной ссылкой; для
  YouTube Music и SoundCloud кнопка открывает страницу сервиса. Подробнее —
  [`docs/discord-rpc.md`](discord-rpc.md).

## Чего здесь нет

- **Яндекс.Музыка** — публичного API для сторонних плееров нет; остаётся только ссылка на
  официальный сервис.
- **Spotify** — полное воспроизведение требует Premium, Web Playback SDK и Widevine. В
  стандартном Electron Widevine отсутствует, поэтому это отдельная сборка castLabs и
  одобрение Spotify.
- **Deezer** — публичный API отдаёт только 30-секундные превью; полный поток требует
  партнёрского договора.

Эти ограничения не обходятся: приложение не использует внутренние API, перехват токенов и
расшифровку DRM.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| «Нужен ключ» | Ключ не сохранён или удалён. Вставьте его заново. |
| «Источник выключен» | Переключатель источника или «Онлайн-источники» в настройках. |
| YouTube: «quota exceeded» | Дневная квота проекта исчерпана; подождите или создайте другой проект. |
| YouTube: ошибка 153 / «Ошибка настройки видеоплеера» | Так ведут себя старые сборки с `file://`-origin. В текущей версии интерфейс отдаётся с `http://127.0.0.1`, и плееру хватает referrer. |
| YouTube: видео не играет | Автор запретил встраивание, либо действует возрастное или региональное ограничение. Нажмите «Открыть в YouTube Music». |
| SoundCloud: `401`/`403` | Приложение не одобрено или `client_id` отозван. |
| Плеер пустой | Проверьте интернет и не блокирует ли сеть `youtube.com` / `soundcloud.com`. |
