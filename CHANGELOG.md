# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [Semantic Versioning](https://semver.org/lang/ru/).

## [1.3.2] — 2026-10-23

### Добавлено

- **Проверка `status.embeddable` и запасной вариант для YouTube.** Поиск YouTube
  запрашивает у официального API разрешение на встраивание. Если автор его запретил,
  строка помечается, не запускает плеер и предлагает «Открыть в YouTube Music».
  Если API разрешил, а сам плеер всё равно отказал (возрастной фильтр, лицензия,
  регион, коды 101/150), приложение запоминает это и показывает ту же кнопку.
  «Играть всё» пропускает такие видео и запускает следующий доступный трек.
- **Discord Rich Presence.** В настройках появился необязательный переключатель:
  текущий трек, исполнитель, состояние воспроизведения и обложка показываются в
  профиле Discord как «Слушает». Обложка берётся по публичному https-адресу
  (Internet Archive, YouTube, SoundCloud); локальная картинка в Discord не
  отправляется. Для открытых записей Internet Archive добавляется кнопка
  «Скачать» с прямой публичной ссылкой; для YouTube Music и SoundCloud — кнопка
  «Открыть» на страницу сервиса; для локальных файлов — «Найти в YouTube Music»
  по исполнителю и названию. Свободный второй слот занимает кнопка «Скачать
  Kolaars Music» со ссылкой на GitHub Releases; у записей Internet Archive оба
  слота заняты треком. Официальный Application ID уже встроен, поэтому включать
  функцию можно без создания собственного приложения Discord; поле в настройках
  нужно только для форков и отдельных сборок.

### Исправлено

- **Карточка YouTube-плеера была ниже допустимого размера.** При ширине 320 px
  область видео получалась 320 × 180 px, а официальный плеер требует не меньше
  200 × 200 px. Теперь высота области — 200 px.

## [1.3.1] — 2026-10-21

### Исправлено

- **Кнопка «Свернуть» на экране воспроизведения нажималась только самым краем.**
  Верхние 46 px окна заняты drag-зоной заголовка, и она перехватывает нажатия
  независимо от `z-index`: полноэкранный оверлей лежал поверх, но клики до кнопки
  не доходили — работала лишь пара нижних пикселей. Теперь полоса экрана сама
  двигает окно, а её кнопки помечены `no-drag` и нажимаются целиком.
- **Подсказка кнопки противоречила подписи.** Кнопка называется «Свернуть», а
  подсказка говорила «Закрыть (Esc)» — теперь «Свернуть (Esc)».

## [1.3.0] — 2026-10-20

### Добавлено

- **Экран «Источники»: YouTube Music и SoundCloud.** Поиск идёт через официальные API
  (YouTube Data API v3 и публичный API SoundCloud), а звук воспроизводит официальный
  встроенный плеер сервиса — IFrame Player или SoundCloud Widget. Приложение не извлекает
  поток, не обходит DRM и не скачивает защищённую музыку.
- **Зашифрованные ключи.** Ключи API вводятся на экране «Источники», шифруются через
  `safeStorage` (DPAPI / Keychain / libsecret) и лежат отдельно от библиотеки. Рендерер
  получает только состояние «ключ сохранён», а параметры `key`/`client_id` вырезаются из
  текстов ошибок.
- **Внешние треки в общей очереди.** Повтор, перемотка, громкость, избранное и плейлисты
  работают как с обычными записями. Внешний трек попадает в библиотеку, когда вы добавляете
  его в избранное или плейлист, — тогда ссылка переживает перезапуск.
- Подробная инструкция по подключению — [`docs/sources.md`](docs/sources.md).

### Исправлено

- **YouTube-плеер падал с ошибкой 153.** Официальный IFrame Player отклоняет страницы
  с `file://`-origin: запрос приходит без HTTP-referrer. Собранный интерфейс теперь
  отдаётся встроенным HTTP-сервером только на `127.0.0.1` (порты 41723–41727), поэтому
  у страницы есть обычный origin и referrer. Сервер отдаёт лишь файлы интерфейса и не
  выходит за пределы компьютера.
- **Медленное восстановление сессии могло перехватить уже выбранный трек.** Метаданные
  восстанавливаемой записи загружаются асинхронно; если за это время пользователь включал
  другой трек, старый загрузчик мог подменить источник звука. Теперь восстановление
  проверяет, что текущий трек всё ещё тот же, и отменяется при смене.
- **Позиция и караоке замирали, когда окно перекрыто другим приложением.** Тикер плеера
  работал на `requestAnimationFrame`, который Chromium останавливает у невидимого окна:
  звук продолжал играть, а полоса и подсветка строки застывали. Теперь позицию
  дополнительно синхронизирует `timeupdate` самого аудиоэлемента, а рендерер не уходит в
  фоновый режим при перекрытии окна.

### Изменено

- **Проверки собранного интерфейса.** `npm run smoke` теперь дополнительно убеждается, что
  страница отдаётся с `http://127.0.0.1`, а CSP разрешает официальные плееры;
  `npm run smoke:packaged` повторяет эти проверки уже на упакованном приложении.
- **Документация.** Подключение ключей, ограничения сервисов и объяснение ошибки 153
  собраны в [`docs/sources.md`](docs/sources.md).

## [1.2.2] — 2026-10-19

### Исправлено

- **Перемотка локальных файлов не работала вовсе.** Схема `kmedia://` отдавала файл одним
  куском и игнорировала `Range`-заголовок, поэтому браузер считал поток не подлежащим
  перемотке (`audio.seekable` был пустым): полоса перемотки не двигала трек, а переход к
  строке текста или к сохранённой позиции начинал песню заново. На этом и было основано
  наблюдение, что «клик по строке текста возвращает текст в начало» — в 1.2.1 центр списка
  перестал уезжать, но сам звук по-прежнему откатывался к началу. Обработчик схемы теперь
  разбирает `Range` вручную и отвечает `206 Partial Content` с `Content-Range`,
  `Content-Length` и `Accept-Ranges: bytes` (`src/main/byteRange.ts`), а `Content-Type`
  берётся из расширения файла. `audio.seekable` покрывает трек целиком.
- **Редактор текста мог открыться пустым — и сохранение затирало текст трека.** Тексты
  загружаются по треку, и окно редактора могло быть открыто раньше, чем они пришли (клик по
  меню сразу после смены трека — как раз такой случай): черновик оставался пустым, а
  «Сохранить» записывал пустоту поверх уже сохранённого текста. Теперь черновик подхватывает
  текст, как только тот загрузился, — но только пока автор ничего не напечатал сам
  (`LyricsWorkshop`, флаг `pristine`).

### Изменено

- `npm run test:range` — 33 юнит-проверки разбора `Range`-заголовков и типов содержимого:
  открытые с обоих концов диапазоны, суффикс `-500`, запрос за концом файла, многосоставные и
  мусорные заголовки, которым положено отдавать файл целиком.
- `npm run smoke` проверяет, что локальный файл перематывается на всю длину и что нажатие
  строки текста сдвигает воспроизведение в её время (раньше проверялась только подсветка), а
  редактор текста обязан дождаться и показать сохранённый текст.
- `npm run smoke:packaged`: фикстура стала длиннее буфера, который браузер набирает вперёд,
  поэтому перемотка в конец файла действительно проверяет поддержку диапазонов — и до, и
  после перезапуска приложения.

## [1.2.1] — 2026-10-19

### Исправлено

- **Меню было не нажать мышью.** Слушатель `pointerdown` в capture-фазе закрывал меню
  раньше, чем успевал сработать клик по пункту, поэтому «Редактировать текст» и «Удалить
  пользовательский текст» не выполнялись. Теперь нажатие внутри панели меню его не закрывает,
  а прокрутка закрывает меню только если уехал сам его якорь.
- **В панели текста кнопка закрытия перекрывала меню.** Крестик дока лежал ровно поверх
  кнопки «Действия с текстом», так что любое нажатие по ней закрывало панель. Между ними
  добавлен зазор.
- **Клик по строке текста уводил не к той строке.** Позиция строки считалась от ближайшего
  позиционированного предка, а не от контейнера прокрутки (на 89 px выше — ранние строки
  упирались вверх), и авто-прокрутка продолжала двигать список под курсором. Теперь
  центрирование считается по прямоугольникам, автопрокрутка срабатывает только когда активная
  строка выходит из средней зоны, а при наведении и 4 секунды после действия она на паузе.
- **Сохранение текста из вкладки «Текст»** больше не оставляет устаревшую караоке-разметку:
  строки сопоставляются с новым текстом сначала по содержимому, потом по позиции.
- **Полоса перемотки на большом экране** была короткой, потому что жила в колонке обложки.
  Теперь она занимает всю ширину окна в нижней панели рядом с кнопками управления; дорожка и
  ползунок крупнее. Правила `--lg` переопределялись более специфичными `input[type='range']`,
  поэтому размеры не применялись.
- **После перезапуска приложения** локальные треки и обложки снова доступны: список
  разрешённых путей для `kmedia://` живёт только в памяти и теперь восстанавливается по
  сохранённому профилю при его чтении. Раньше обложки оставались пустыми, а воспроизведение
  отвечало «файл недоступен».
- **Удаление трека** убирает его из очереди, истории и из регистрации в плеере, а не только из
  библиотеки.
- **Вкладка «Источники»** показывает попадания из открытого пака сразу, не дожидаясь сетевого
  ответа Wikisource, и кнопка «Искать» больше не блокируется на время поиска в LRCLIB.

### Добавлено

- **Зерно поверх обложки** на большом экране «Сейчас играет» — как на обложках альбомов.
  Плёночный шум рисуется на canvas, циклично меняется и отключается при
  `prefers-reduced-motion` и в свёрнутом окне.

### Изменено

- Smoke-тест жмёт по интерфейсу настоящей мышью (протокол Chrome DevTools): меню, клик по
  строке текста, редактор и удаление текста — раньше проверки обходили именно те обработчики,
  где были ошибки. Проверка вкладки «Источники» ждёт результат, а не фиксированную паузу.
- `npm run smoke:packaged` перезапускает собранное приложение на том же профиле и проверяет,
  что локальный трек играет и обложка рядом с файлом отрисовывается.

## [1.2.0] — 2026-10-18

### Добавлено

- **Приоритет форматов файлов.** Одна и та же песня часто скачана и как `.flac`, и как `.m4a`.
  Теперь при импорте папки на каждую песню в библиотеку попадает только один файл — лучший по
  порядку из настроек (`Настройки → Формат файлов`, по умолчанию без потерь впереди). Порядок
  меняется кнопками «выше»/«ниже» и сохраняется в профиле. Остальные файлы не добавляются, но
  и не удаляются с диска; их количество показывается в отчёте об импорте. Уже добавленные
  треки не подменяются — иначе разъехались бы плейлисты и избранное.
- **Восстановление символов, запрещённых в именах файлов Windows.** Сервисы заменяют
  `\ / : * ? " < > |` подчёркиванием, и в библиотеке оставались имена вида `Что ты знаешь_`.
  Теперь подчёркивание заменяется на наиболее вероятный символ там, где подсказка однозначна:
  `_` в конце имени → `?` (`Что ты знаешь_` → `Что ты знаешь?`), `_` перед пробелом → `:`
  (`Часть 1_ Начало` → `Часть 1: Начало`), `_` между буквами → `/` (`AC_DC` → `AC/DC`).
  Серия подчёркиваний (`hate music ^__`), ведущее подчёркивание и `_` между пробелами
  остаются как есть: неверная догадка хуже видимого подчёркивания. Правило применяется ко
  всему, что берётся из имени файла, и не трогает теги.

### Изменено

- Импортёр сортирует файлы по приоритету форматов и возвращает в результате список
  пропущенных дубликатов (`duplicates`), а интерфейс показывает их в отчёте.
- `npm run test:names` — 32 юнит-проверки восстановления символов; `npm test` запускает все
  три группы.
- Smoke-тест дополнительно проверяет восстановление «?» в имени и пропуск второго формата
  той же песни.

## [1.1.1] — 2026-10-18

### Добавлено

- **Поддержка выгрузки из музыкальных сервисов.** Такая папка приходит без единого тега, и
  раньше каждый трек попадал в библиотеку как «Неизвестный исполнитель» с названием во весь
  файл, без обложки и без длительности. Теперь это разбирается как есть:
  - **имя файла как источник имён**: `Исполнитель - Название` из имени, если тегов нет (тег
    всегда важнее имени). Дефис внутри названия вторым разделителем не считается;
  - **обложка отдельным файлом**: ищется картинка рядом с треком — `Трек.flac.cover.jpg` (так
    пишет Яндекс Музыка), `Трек.flac.jpg`, `Трек.cover.jpg`, `Трек.jpg`, `cover.jpg`,
    `folder.jpg`. Поиск не зависит от регистра; каталоги и пустые файлы не принимаются.
    Картинка не копируется — она открывается там, где лежит;
  - **длительность из декодера**: контейнеры, которых не понимает `music-metadata` (например,
    FLAC внутри MP4 — так выглядят «`.flac`» из выгрузки), теперь получают длительность при
    первом воспроизведении, и список перестаёт показывать пустое место.
- Юнит-проверки `npm run test:covers` (32 проверки) для поиска обложки рядом с файлом.
  Обе группы юнит-проверок идут под `npm test` и подключены в CI.

### Изменено

- Smoke-тест дополнительно проверяет импорт папки без тегов, где обложки лежат отдельными
  файлами по двум разным соглашениям именования.

## [1.1.0] — 2026-10-18

### Добавлено

- **Локальные профили**: несколько независимых библиотек на одном компьютере. У каждого
  профиля свои треки, плейлисты, избранное, тексты, обложки и офлайн-загрузки — целиком в
  каталоге `userData/profiles/<id>/`. Переключение, создание, переименование и удаление в
  настройках; единственный профиль удалить нельзя. Это не аккаунты: ни входа, ни сети.
- **Импорт списка треков** из другого сервиса: вставьте строки «Исполнитель — Название» или
  откройте `.txt`, `.csv` (в том числе с заголовком в любом порядке колонок), `.tsv`,
  `.m3u`/`.m3u8`. Строки дедуплицируются, предпросмотр показывается до запуска.
- **Сопоставление** каждой строки: сначала с собственной библиотекой, затем (по желанию) с
  открытым архивом Internet Archive, затем с LRCLIB для текстов. Результат сохраняется
  плейлистом с отчётом: найдено локально / в архиве / без звука / текстов сохранено.
- **Экспорт плейлиста** в M3U8, CSV или JSON. Ссылки на звук не выгружаются никогда; в M3U8
  попадают только пути к вашим локальным файлам, а строки без файла сохраняются
  комментариями, чтобы чужие плееры их просто пропускали.
- Пункт меню «Импортировать список треков…» (`Ctrl+Shift+L`).
- Юнит-проверки `npm run test:tracklist` (33 проверки) для разбора списков и экспорта,
  подключённые в CI.

### Изменено

- **Схема хранения**: документ `kolaars.json` переехал в каталог профиля. Каталог данных от
  версии 1.0.0 переносится в профиль «Основной» при первом запуске — существующая библиотека
  сохраняется. Реестр профилей — `profiles.json` в корне каталога данных.
- Трек без звуковой ссылки теперь сообщает об этом понятнее: «У этого трека нет звука —
  сохранены только название и текст».

### Документация

- README: разделы про профили, импорт/экспорт списков и **явное описание того, чего
  приложение не делает** — оно не обращается к Яндекс.Музыке, Spotify и Genius: их правила
  запрещают автоматический доступ, а тексты песен охраняются авторским правом. Для
  защищённой музыки свободного источника звука не существует, поэтому такая строка
  сохраняется как название и текст без аудио.

## [1.0.0] — 2026-10-18

Первый публичный выпуск.

### Добавлено

- **Обзор** с десятью подборками открытой музыки из Internet Archive (Great 78 Project,
  Musopen, Netlabels): подборки показываются мгновенно из встроенного каталога, затем
  дополняются свежими результатами поиска.
- **Поиск** по Internet Archive с постраничным выводом, ограничением по коллекции и
  сортировкой по популярности.
- **Библиотека** с импортом файлов и папок, чтением тегов и обложек через `music-metadata`.
- **Избранное, плейлисты и очередь** воспроизведения, режимы перемешивания и повтора.
- **Загрузки** для офлайн-прослушивания со страницы загрузок.
- **Тексты песен**: встроенный сборник из 65 песен общественного достояния, синхронизация
  LRC, онлайн-поиск через LRCLIB и Wikisource по явному действию пользователя.
- **Мастерская текстов**: ручная правка, синхронизация по клику, импорт и экспорт `.lrc`.
- **Интерфейс**: тёмная и светлая темы, настраиваемый акцент, полноэкранный режим «Сейчас
  играет», панели текста и очереди, справочник клавиатурных сокращений, поддержка
  медиа-клавиш Windows.
- **Безопасность**: изолированный рендерер (`contextIsolation`, `sandbox`), привилегированная
  схема `kmedia://` со списком разрешённых путей, строгий CSP, открытие внешних ссылок в
  системном браузере.
- **Хранение**: единый документ `kolaars.json` с атомарной записью и debounce, восстановление
  после повреждения файла.
- **Инструменты разработчика**: генератор иконок, сборщик встроенного каталога, подготовка
  офлайн-кэша `electron-builder`, smoke-тест интерфейса по протоколу Chrome DevTools и
  отдельный smoke-тест собранного приложения (`npm run smoke:packaged`), который проверяет
  загрузку из `app.asar`, чтение тегов и воспроизведение локального файла через `kmedia://`.
